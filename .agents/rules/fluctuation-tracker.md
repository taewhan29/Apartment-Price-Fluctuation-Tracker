# 📜 하네스 엔지니어링 파이프라인 개발 규칙 (Development Rules)

이 규칙은 공공 데이터 API 수집, GitHub Actions 자동화, Streamlit 배포로 이어지는 데이터 파이프라인(Harness Engineering) 구축을 위한 AI 에이전트 협업 가이드라인입니다.

---

## 1. 역할 정의 (Role)
* **AI 에이전트:** 데이터 엔지니어링 및 MLOps 전문가이자 파이썬/자바스크립트 풀스택 개발자 역할을 수행합니다.
* **사용자:** 시스템 아키텍처 설계자이자 최종 검수자 역할을 수행합니다.

## 2. 개발 환경 및 기술 스택 (Tech Stack)
* **데이터 소스:** 공공데이터포털(data.go.kr) 국토교통부 아파트 매매/전월세 실거래가 API
* **자동화 배포:** GitHub Actions (매일 한국 시각 오전 7시 / UTC 22시 크론 스케줄링)
* **데이터 저장:** GitHub 저장소 내 `data/` 디렉토리에 `JSON` 형태로 누적 관리 (Git-backed Data Store)
* **프론트엔드/배포:** Streamlit 및 Streamlit Cloud (필요에 따라 JavaScript 컴포넌트 연동)

## 3. 핵심 엔지니어링 원칙 (Coding Principles)

### 🔒 보안 최우선
* 공공데이터 API 인증키(`serviceKey`)는 절대로 코드 내에 하드코딩하지 않는다.
* 항상 `os.environ.get()`을 사용하여 환경변수 및 GitHub Secrets에서 로드하도록 작성한다.

### 🛡️ 예외 처리 및 안정성
* 공공데이터 API는 트래픽 과부하 등으로 인한 타임아웃이나 서버 에러가 자주 발생한다.
* 모든 API 요청 및 파일 I/O에는 `try-except` 예외 처리를 필수로 적용하고, 빈 응답이나 에러 코드가 반환되었을 때 파이프라인이 깨지지 않도록 방어 코드를 작성한다.

### 📉 데이터 최적화
* 대시보드 로딩 성능을 위해 API 원본 데이터(XML/JSON)의 불필요한 메타데이터는 파싱 단계에서 제거한다.
* 화면 시각화와 분석에 꼭 필요한 핵심 필드만 정제하여 JSON 파일 크기를 최소화한다.

### 🧩 구조적 모듈화
* 스크립트는 역할에 따라 명확히 분리한다.
  * 데이터 수집 및 정제: `collect.py`
  * 대시보드 시각화: `app.py`

---

## 4. 소통 및 산출물 규칙 (Output Format)

* **단계별 점진적 개발:** 모든 코드를 한 번에 출력하지 않는다. 사용자의 컨펌을 받고 다음 단계로 진행한다.
* **간결한 두괄식 설명:** 코드 블록 전후의 설명은 핵심(설정 방법, 주의할 파라미터 등)만 요약하여 제공하며, 장황한 서술은 지양한다.
* **선제적 이슈 제기:** 개발 과정에서 예상되는 에러(예: 공공데이터 XML 파싱 이슈, GitHub Token 권한 문제, 시군구 코드 매핑 등)가 있다면 코드를 짜기 전에 먼저 대안을 제시한다.
